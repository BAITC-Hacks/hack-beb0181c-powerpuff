# Интерфейс EKT

Существующая главная `/` сохранена. Ссылка «Ассистент EKT» открывает `/assistant`, демонстрационная корзина находится на `/cart`.

## Запуск

Нужен Node.js 20.19+ или 22.12+ (требование установленного Vite 8), и запущенный backend. Из корня:

```sh
cd frontend
npm ci
# При необходимости скопируйте .env.example в .env.local и настройте адреса.
npm run dev -- --host 127.0.0.1 --port 5174 --strictPort
```

Откройте http://localhost:5174/assistant. Порт 5174 выбран, потому что 5173 занят другим локальным проектом. Не останавливайте его. Все страницы одной сессии открывайте через один hostname: localhost и 127.0.0.1 имеют разные sessionStorage.

По умолчанию запросы `/api` проксируются Vite на `http://localhost:8080`. `BACKEND_PROXY_TARGET` изменяет адрес proxy. `VITE_API_BASE_URL` задаёт прямой адрес API вместо proxy; при таком режиме backend должен разрешать origin frontend. Переменные VITE_* публичны: не помещайте туда EKT/OpenAI ключи. Перезапустите Vite после изменения конфигурации.

В корневом серверном `.env` для этого запуска задайте `FRONTEND_BASE_URL=http://localhost:5174` и включите `http://localhost:5174` в `CORS_ORIGINS`, сохранив остальные нужные origins. Тогда `cartUrl` backend ведёт на рабочую `/cart`. Для порта 5173 поменяйте обе настройки соответственно.

Backend запускается из IDE на Java 21 с переменными корневого `.env` в конфигурации запуска; Spring Boot сам `.env` не читает. Альтернатива из корня (только для собственного доверенного `.env`):

```sh
docker compose up -d --wait db
set -a
. ./.env
set +a
cd backend
./mvnw spring-boot:run
```

Не запускайте второй backend поверх экземпляра из IDE. Подробные настройки и контракт: [backend README](../backend/README.md), [API](../backend/docs/frontend-api.md).

## Режим без LLM

Текст ищет название или артикул. Сообщения — шаблоны по фактическому ответу API. Ни `/api/chat`, ни OpenAI, ни ML не вызываются; LLM_API_KEY для интерфейса не нужен. Код LLM backend сохранён.

`src/assistant/api.ts` — типизированный HTTP-клиент; `useAssistant.ts` — действия и состояние; `components.tsx` и `AssistantPage.tsx` — отображение. Токен хранится в sessionStorage вкладки. При истечении нужна явная новая сессия; операции корзины не воспроизводятся автоматически. Старые поисковые запросы отменяются.

Кнопка добавления создаёт предложение с UUID, но не меняет корзину. Изменение происходит после явного подтверждения revision. Обновлённые условия требуют ещё одного подтверждения. Повторные нажатия блокируются. Реальные заказы, резервы и корзина ekt.kz не интегрированы. В /cart доступны карточка товара, редактирование целевого количества и удаление с подтверждением.

## Проверки 23.09.2026

`npm run build` и `npm run lint` проходят. В браузере на реальном локальном backend проверены desktop 1440×1000 и mobile 390×844:

- Артикул `200300285_`: поиск, карточка 515291, склады, конфликт `160А / 250 А` в строке характеристики; горизонтального переполнения нет.
- Артикул `310100024_`: товар 21182 отсутствует, подтверждённых аналогов нет; сообщение предлагает уточнить подбор.
- Предложение 515291 оставило корзину пустой; после подтверждения `/cart` показала одну позицию с количеством 1.
- Искусственно задержанный настоящий ответ поиска `Legrand` не заменил более новый результат `310100024_`; обращения к LLM/ML в этой проверке отсутствовали.
- После имитации отказа соединения в браузере кнопка «Повторить загрузку» восстановила настоящую карточку.
- Истёкшая сессия потребовала отдельную кнопку создания новой сессии, новая корзина пуста.
- Неутверждённые условия показаны явно.
- Backend действительно остановлен для проверки: ошибка видна внутри мобильной карточки, возврат к результатам работает; затем backend восстановлен, `/api/health` отвечает `ok`.

Это браузерные проверки, не постоянный автоматический E2E-набор. Положительный сценарий реального подтверждённого аналога не проверен: подходящая пара в доступных данных не найдена. Отрисовка кандидатов реализована с объяснением и предварительным статусом. Образец с сертификатом также не найден; наличие ссылок нельзя объявлять проверенным. Условия покупки, валюта, единицы, продаваемые склады и резервы требуют подтверждения партнёра. Похожие названия не используются интерфейсом для вывода о совместимости.

Для production нужен reverse proxy `/api` и fallback маршрутов `/assistant`, `/cart` на `index.html`: Vite dev proxy не входит в статическую сборку. HTTPS и deployment в этой задаче не выполнялись.

## Редактирование корзины и главная

В позиции доступны изображение, название, артикул, цена, подтверждённое количество и сумма. Изображение и название открывают общий компонент Detail по productId, без перехода со страницы; закрытие восстанавливает прокрутку. Поле и кнопки «−/+» меняют только черновик. «Применить» отправляет целевое количество с requestId и version. При неизвестной кратности шаговые кнопки недоступны; количество можно ввести вручную. Сервер проверяет известные правила.

При увеличении нужна свежая карточка EKT; другая цена открывает отдельное подтверждение. При уменьшении цена остаётся сохранённой, EKT не вызывается. Удаление выполняется отдельной кнопкой и после диалога; ноль товар не удаляет. UI блокирует повторные действия по позиции, выводит ошибку рядом с ней и берёт суммы из ответа backend. При конфликте версии нажмите «Обновить» и подтвердите нужное изменение заново.

На главной добавлена плавающая кнопка ассистента по референсу: её можно свернуть, она ведёт в /assistant. Поиск в шапке передаёт название или артикул через /assistant?q=...; LLM не используется. WhatsApp перенесён в footer. Исходные баннеры и ссылки категорий сохранены.

Проверка 23.09.2026: real EKT, desktop 1440×1000 и mobile 390×844. Карточка 515291 открывается по названию и изображению, виден конфликт 160/250 А. Поле 2→3 не меняет сервер до «Применить»; применение и повтор одного запроса оставляют 3, после reload данные сохраняются, итог backend пересчитан. Превышение остатка показывает ошибку. Для проверки без EKT был временно запущен backend на 8081 с app.ekt.enabled=false; браузерные PUT/DELETE направлены на него с сохранением настоящих запросов/ответов. Уменьшение и удаление прошли; последний товар дал пустое состояние после reload. Временный backend остановлен. Главная, launcher, его сворачивание и поиск из шапки также проверены в браузере; горизонтального переполнения нет.
