# Контракт backend для фронтенда

Backend: `http://localhost:8080`. Все тела — JSON. CORS_ORIGINS должен содержать адрес фронтенда.
Ошибки: ProblemDetail `{status, detail, code?}`; ошибки валидации дополнительно содержат `errors`.

## Каталог

- `GET /api/products/search?q=Legrand&page=0&size=20` — поиск в PostgreSQL, size ≤ 100.
- `GET /api/catalog/products?page=0&size=20` — список из PostgreSQL.
- `GET /api/catalog/products/{id}` — сохранённая карточка: `{product, listUpdatedAt, detailUpdatedAt, detailError, warnings}`.
- `GET /api/products/{id}` — свежая карточка EKT.
- `GET /api/products?page=1` — страница из EKT (здесь page начинается с 1).
- `GET /api/catalog/status` — полнота и статус импорта.
- `GET /api/products/{id}/analogs` — кандидаты с объяснением и ограничениями.
- `GET /api/purchase-terms` — условия; `verified:false` означает, что источник пока не предоставлен.

В каталоге нет подтверждённого поля сертификата. Ссылки и исходные свойства передаются
как есть; не показывайте придуманные сертификаты. Конфликт токов в карточке отмечается
`NOMINAL_CURRENT_CONFLICT`. Алгоритм аналогов пропускает такие карточки.

## Сессия

`POST /api/session` без тела:

```json
{"token":"<непрогнозируемый токен>","tokenType":"Bearer","expiresAt":"..."}
```

Передавайте `Authorization: Bearer <token>` для корзины и чата.
Токен действует 24 часа. На сервере хранится только его хеш.
После истечения сессии данные удаляются фоновым заданием в течение 5 минут.
При 401 создайте новую сессию. Не помещайте токен в URL.

## Корзина

`GET /api/cart` возвращает `{items, cartUrl, mode:"LOCAL_DEMO", stockReserved:false}`.
Корзина сохраняется в PostgreSQL, не резервирует товар и не создаёт заказ EKT.

`POST /api/cart/proposals`:

```json
{"requestId":"<UUID запроса>","productId":515279,"quantity":1}
```

Ответ — предложение `{id, productId, name, quantity, price, stock, revision, status, expiresAt}`.
Создание предложения **не меняет корзину**. Новый requestId создаёт новое предложение,
предыдущее неподтверждённое становится SUPERSEDED. Повтор requestId с тем же товаром
и количеством возвращает прежнее предложение, с другими данными — 409.

Покажите товар, количество и цену, затем кнопку подтверждения.
`POST /api/cart/proposals/{id}/confirm`:

```json
{"revision":1}
```

Ответ: `{added, requiresConfirmation, proposal, cart}`.
Если `requiresConfirmation:true`, корзина не изменена: покажите обновлённые данные
и запросите подтверждение с новым revision. Недостаточный остаток — 409
INSUFFICIENT_STOCK; предложите пользователю изменить количество, не уменьшайте его автоматически.
Предложение действует 10 минут. Повтор подтверждения не дублирует товар.

`cartUrl` строится как `${FRONTEND_BASE_URL}/cart`.
**Страницу /cart должен реализовать фронтенд:** читать GET /api/cart с тем же токеном.
Это не ссылка на корзину ekt.kz; интеграция с его корзиной не предоставлена.

## Чат

`POST /api/chat`:

```json
{"messageId":"<UUID сообщения>","text":"Найди Legrand"}
```

Ответ: `{messageId, text, data}`. data содержит карточки, предложение, условия
или результат подтверждения. Повторите тот же messageId и text при сетевом сбое;
готовый ответ будет возвращён из БД, без повторения действия.
MESSAGE_IN_PROGRESS — предыдущая обработка того же ID ещё не завершена.
На сессию допускается до 100 сообщений, текст до 4000 символов.

Модель выбирает действие, backend вызывает разрешённый сервис и формирует ответ
из данных. Она не получает инструмент изменения корзины или оформления заказа.
Текстовое подтверждение принимается только как точная фраза «да, добавь» или
«да добавь» для единственного активного предложения. Остальные формулировки
не изменяют корзину. Предпочтительный путь UI — кнопка с id и revision.

Чат требует LLM_API_KEY и LLM_MODEL. Без них — 503 LLM_NOT_CONFIGURED.
Используется OpenAI Responses API, store=false; сохраняется до 5 предыдущих
обменов для контекста в запросе к провайдеру. Внешнее качество модели и задержка
без ключа не проверены. Числовые последовательности, похожие на платёжные номера,
маскируются; не предлагайте вводить платёжные реквизиты в чат.

## Что остаётся внешней настройкой

- Ключ и модель OpenAI в окружении запуска backend.
- Утверждённые условия EKT через PURCHASE_TERMS_FILE.
- Страница корзины фронтенда и её origin.
- Полный импорт данных: пока в локальной БД демонстрационная выборка.
- Правила доступности складов, единицы и валюта требуют подтверждения партнёра.

PDF/Excel/Word/фото-вложения, казахский язык и передача диалога менеджеру пока
не реализованы. Текущий backend принимает текстовые сообщения.
