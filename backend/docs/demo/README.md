# Демо: товара нет, совместимая замена не доказана

**Обновление:** конфликт 160/250 А и основной текст отказа теперь исправлены.
Исторический прогон ниже сохраняет результаты исходной выборки; актуальные изменения,
правила и состояние расширенного импорта описаны в [новом отчёте](../backend-hardening.md).
В текущей демо-коллекции конфликт проверяется успешным тестом, а не Skipped.

Проверено 23 сентября 2026 на локальном backend, реальном EKT API и настроенной LLM.
**Сценарий отсутствия товара подтверждён. Положительный сценарий доступного совместимого
аналога пока не закрыт.** Похожие названия и `RECOMMEND` не являются доказательством.

## Данные и результаты

Импортированы четыре дополнительные страницы и 80 подробных карточек штатным
профилем `catalog-sync`. Теперь в БД 100 товаров, все с деталями; ошибок импорта 0.
Следующая страница — 6, `list_complete=false`, остановка `PAGE_LIMIT` ожидаема.
Полный каталог не выгружен. У 52 товаров сохранённый остаток равен нулю; ни у одного
из этих 52 нет всех шести обязательных полей текущего алгоритма. Все 52 вызова
подбора вернули пустой список. Это вывод только о выборке, не обо всём каталоге EKT.

## Что показать на демо

Импортируйте коллекцию, задайте `baseUrl=http://localhost:8080`, выберите
**No environment**, выполните все 13 запросов по порядку, одна итерация.
`sessionId` заполняется автоматически. Backend должен работать с PostgreSQL и EKT;
последние два запроса требуют LLM. Коллекция проверяет именно зафиксированный сценарий:
если реальные остатки или данные изменятся, проверки должны упасть.

1. Поиск `EKT_DEMO_MISSING_20260923_7E3C` возвращает 200 и пустой `items`.
   Это отсутствие результата в локальной выборке, не доказательство отсутствия у поставщика.
2. `GET /api/catalog/products/9223372036854775807` возвращает 404 для ID,
   отсутствующего в локальной БД. Это отдельный случай от нулевого остатка.
3. `GET /api/products/21182` возвращает реальную карточку
   **11204 ВА 63 (1ф) 20А 404029 Legrand (10) !!!**, артикул `310100024_`,
   цена 941, остаток **0** на момент проверки.
4. `GET /api/products/21182/analogs` возвращает `items: []` и объяснение:
   недостаточно непротиворечивых характеристик, нужно уточнение у менеджера.
5. Создайте сессию через `POST /api/session`, затем с её Bearer-токеном отправьте
   `POST /api/cart/proposals`:

   ```json
   {"requestId":"<новый UUID>","productId":21182,"quantity":1}
   ```

   Ответ — 409 `INSUFFICIENT_STOCK`. `GET /api/cart` подтверждает пустую корзину.
6. `GET /api/products/33703` показывает доступный товар для сравнения:
   **12120 АВ (1ф) 20А Schneider Electric (12)**, артикул `010400569_`,
   остаток **108**. **Не представлять его совместимым аналогом.**
7. В одной сессии отправьте в `POST /api/chat` два сообщения, каждый раз с новым `messageId`:

   ```json
   {"messageId":"<новый UUID>","text":"Покажи карточку товара ID 21182 и его остаток."}
   ```

   ```json
   {"messageId":"<другой UUID>","text":"Подбери доступный аналог этого же товара. Совместимость обоснуй характеристиками, не названием и не RECOMMEND."}
   ```

   Первый ответ: карточка 21182 с остатком 0. Второй: пустой `data.items` и причина
   в `data.message`. В текущем общем `text` чата причина отсутствия кандидатов
   не повторяется; интерфейс должен показывать `data.message`.

## Почему 33703 не подтверждён как замена

| Поле из EKT | 21182, нет в наличии | 33703, есть в наличии |
|---|---|---|
| Полюса | 1 | 1 |
| Номинальное напряжение | 230В | 230В |
| Номинальный ток | 20А | 20А |
| Характеристика срабатывания | C | C |
| Отключающая способность | 4,5кА | 20кА |
| Крепление | Не заполнено | На Din-рейку ( Модульный ) |
| `OBYEM`, обязательное поле типа текущего алгоритма | Не заполнено | Не заполнено |

Совпадений тока и полюсов недостаточно. Значение отключающей способности отличается;
его корректность, допустимость замены, крепление и габариты требуют проверки источника
и специалиста. Нельзя заполнять пропуски догадкой из названия или автоматически
считать большее числовое значение достаточным. Исходные свойства не исправлялись.

## Незакрытые требования и найденные дефекты

| Требование | Статус и следующий шаг |
|---|---|
| Доступный совместимый аналог отсутствующего товара | Не подтверждён. Нужна реальная пара с полными согласованными данными и проверка применимости специалистом; текущая выборка такой пары не дала |
| Выявление противоречий характеристик | Найден дефект: у 515291 название содержит 160А, свойство `NOMINALNYY_TOK` — 250 А, но `warnings` пуст. Регулярное выражение использует `(?i)` без Unicode case folding и не распознаёт заглавную кириллическую «А» как строчную «а». Требуется исправление и регрессионный тест |
| Полнота правил аналогов | Текущий алгоритм сравнивает шесть строковых полей и ограничен автоматами. Нужны согласованные правила категорий, нормализации единиц, характеристики срабатывания, габаритов, дополнительных критичных параметров и проверки противоречий. Даже шесть совпадений дают только кандидата |
| Свежая доступность аналога | Подбор читает остаток из БД на момент импорта. Перед предложением нужно получить свежую карточку; корзина уже перепроверяет остаток через EKT |
| Реакция чата на отсутствие аналога | Причина есть в `data.message`, но общий `text` не сообщает явно, что кандидатов нет. Автоматический переход от нулевого остатка к подбору не реализован: демо использует отдельный следующий вопрос |
| Полнота каталога | 100 карточек — демонстрационная выборка; полный обход не выполнен |
| Утверждённые условия покупки | Источник партнёра не предоставлен, `verified=false` |
| Правила доступных складов, валюта и единицы | Требуют подтверждения партнёра; общий положительный остаток не доказывает возможность отгрузки с конкретного склада |
| Сертификаты, вложения, казахский язык, передача менеджеру | Отдельные полноценные сценарии не реализованы/не проверены; не заявлять их готовность |
| Реальная корзина/заказ EKT | Только локальная демонстрационная корзина без резервирования. Интеграция с заказом EKT не предоставлена; frontend `/cart` отдельно этим прогоном не проверен |

В демо-коллекции две проверки явно помечены Skipped: положительный подбор аналога
и известный дефект предупреждения о конфликте. Они не считаются закрытыми даже
при нулевом количестве Failed. Код подбора в рамках этого аудита не изменялся.

Демо-коллекция проверена Newman 6.2.2: 13 запросов, 23 проверки —
21 прошла, 2 пропущены, ошибок выполнения нет. Оба реальных запроса LLM вернули 200.

```bash
  --timeout-request 45000 --delay-request 250
```
